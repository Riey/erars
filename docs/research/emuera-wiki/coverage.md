# Emuera wiki ⇄ erars **runtime** coverage

Generated by `cargo test -p erars --test wiki_coverage -- --nocapture`;
do not hand-edit. Names come from `index.md`, mechanically.

Every verdict is a real run through preprocess → parse → compile →
`FunctionDic` → `TerminalVm::start(@SYSTEM_TITLE)`, never a source-table diff:
an unknown `NAME(...)` parses fine as `Expr::Method`
(`crates/erars-compiler/src/parser/expr.rs:540`) and only faults when executed.

* `absent` — the name resolved to nothing: `[lexer] Unknown line`
(`crates/erars-lexer/src/lib.rs:845`, `:912`), `[lexer] Unknown sharp line` (`:826`),
`Function X is not exists` (`crates/erars-vm/src/function.rs:337`) or
`Variable X is not exists` (`crates/erars-vm/src/variable.rs:832`, `:995`).
* `present` — the name resolved and then refused this probe (arity, type,
semantics). **An argument error is evidence of presence.**
* `ran` — the name resolved and the line completed.
* `n/a` — the wiki index row is not an Emuera name (scraping artefact).

A ladder of probe shapes is tried per name and the best outcome wins, so
`absent` means *every* shape resolved to nothing.

**Known limitation.** `parse_print_left`
(`crates/erars-lexer/src/utils.rs:287-318`) discards the unparsed remainder of a
`PRINT`-prefixed word, so erars accepts `PRINTZZNOSUCH` as a plain `PRINT`.
This harness therefore cannot prove absence for any `PRINT*` name;
`harness_controls` pins the behaviour.
